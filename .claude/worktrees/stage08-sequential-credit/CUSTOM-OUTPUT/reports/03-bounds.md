## 1. The node-split transform, `L → L*`

`L(G)` has **nodes** that must be visited. Postman problems are defined over
**edges**. Every arc-routing formulation that tries to cover nodes directly is
solving a different problem than the one it thinks it is, so the split comes first
and everything else is built on top of it.

```
a_in ──[ capture:  lower = upper = min_passes(a), cost = capture_time_s(a) ]──▶ a_out
     └─[ deadhead: lower = 0,        upper = ∞,   cost = deadhead_time_s(a) ]─┘

a_out ──[ manoeuvre a → b: cost = turn penalty ]──▶ b_in
```

"Cover arc `a` at least `k` times" is now exactly "traverse the required edge
`(a_in, a_out)` `k` times" — a Directed Chinese Postman with lower bounds, which
min-cost flow with lower bounds solves exactly.

**Two edges, not one.** The stage brief describes a single required edge at
`capture_time_s`. SPEC §6 is more specific: the 40 km/h cap binds on *required*
traversals and "deadhead segments are uncapped". A repeat pass that no requirement
asked for is a deadhead segment, so it is priced at the uncapped speed. Splitting
the edge is the only way to charge the two kinds of traversal differently, and
because `deadhead_time_s ≤ capture_time_s` always, the flow uses the capture edge
exactly `min_passes` times without being told to.

## 2. The constructive upper bound — a real plan

Three steps: orient the narrow pairs, solve the Chinese Postman exactly for that
orientation, extract an Euler circuit. The result is a complete, legal, closed
single tour of Tbilisi.

### 2.1 Orienting the narrow pairs

SPEC §2.1 gives a narrow two-way street a requirement of **one** traversal from
either direction. Fixing which direction removes the generalisation and leaves an
ordinary Directed Chinese Postman — at the cost of making the answer an upper bound.

**Where the imbalance lives.** It is tempting to minimise imbalance on `L*`, and it
would be wasted work: imbalance there is *orientation-invariant*. Every required
edge `a_in → a_out` creates exactly one unit of source and one of sink, and a pair
contributes exactly one required edge whichever way it is turned, so
`Σ|supply| = 2·Σ lower` regardless. The choice only moves *where* the sources and
sinks are. The quantity that does respond is imbalance at the **base network's
junctions**, which is what SPEC §4 means and what the heuristic minimises.

| Measure | Value |
| --- | ---: |
| Narrow pairs | 12,853 |
| Junction imbalance, naive orientation | 10,006 |
| …after the greedy pass | 9,534 |
| **…after local search** | **9,396** |
| Flips: greedy / local search | 950 / 68 |
| Local-search passes to converge | 3 |
| Pairs with only one drivable direction (forced) | 62 |
| Pairs with neither direction reachable | 0 |
| Degenerate pairs (both ends the same junction) | 24 |

The heuristic removes 6.1%
of the junction imbalance. That is a modest gain and it is worth saying so: most of
Tbilisi's imbalance is structural — one-way streets and dead ends — and no choice
of pair direction can remove it.

### 2.2 Balancing, and the part that is actually NP-hard

Min-cost flow with lower bounds balances every node of `L*` exactly and in
polynomial time. **Connectivity is the hard half.** Only some edges are required —
the unoriented half of every narrow pair is free, and so is every manoeuvre — so
the cheapest circulation is free to fall into many separately-balanced pieces, each
internally Eulerian and mutually unreachable. There is no single circuit over that.

Tbilisi does exactly this, and the mechanism is a dead-end two-way street: the
cheapest way to satisfy its one required traversal is to drive in, turn at the tip,
and turn straight back in again — a self-contained two-cycle that touches nothing
else and is perfectly balanced. The flow finds thousands of them.

| Measure | Value |
| --- | ---: |
| Components in the first circulation | 165 |
| Nodes stranded outside the main one | 3,386 |
| Repair rounds to reach one component | 6 |
| Edges forced to connect them | 338 |
| **Balance cost** (the flow optimum) | **87.1 h** |
| **Connectivity cost** (the repair) | **0.9 h** |

The repair costs 0.9 h — 1.0% of the tour. It is a
heuristic (force a cheapest entry into each stranded piece, then re-solve and let
the flow find its own way back out), so a better one would produce a cheaper tour.
It is charged separately above rather than folded into the total, because it is the
one part of the constructive result that is *not* exact.

## 3. The genuine lower bound

Fixing an orientation *adds* a constraint, so §2's tour cannot bound from below —
it is a feasible solution, and feasible solutions bound from above. The bound is
computed separately, from a relaxation of the generalised routing problem over `L*`:

- integrality dropped — traversal counts go continuous;
- the orientation choice returned — each narrow pair carries one
  `y_a + y_b ≥ 1` row instead of a fixed direction;
- connectivity dropped entirely.

All three make it a genuine relaxation, and therefore genuinely below the optimum.

| Method | Bound | Status | Runtime |
| --- | ---: | ---: | ---: |
| **LP relaxation** (used) | **54.4 h** | optimal | 15 s |
| Capture floor + cheapest exit (fallback) | 32.5 h | exact | 0.0 s |

The LP is 229,981 columns and 139,794 rows
(485,682 nonzeros), of which 12,853 rows are
the narrow-pair disjunctions that stop it being a pure network LP. Solved with HiGHS
interior point, single-threaded and seeded so the bound does not wobble between runs.

The fallback is reported alongside rather than discarded: it is rigorous, it costs a
second, and an LP that fell *below* it would be solving a different model. It is
weak because it accounts for no repositioning at all — every required traversal, plus
the cheapest legal way to leave it, and nothing else.

## 4. Where the gap comes from

The gap is **61.8%**, which is wide. It is worth being
precise about which side of it is loose, because the answer decides what Stage 5
should work on.

| Step | Hours | Δ | What it costs |
| --- | ---: | ---: | ---: |
| LP relaxation (lower bound) | 54.4 | — | fractional coverage, free orientation, no connectivity |
| Min-cost flow, one fixed orientation | 87.1 | +32.7 | integrality and the orientation choice |
| **Constructive tour** (upper bound) | **88.0** | +0.9 | connectivity repair |

**Almost all of the gap is bound looseness, not tour slack.** Going from the LP to an
integral single-orientation circulation costs 32.7 h; making that
circulation into one connected tour costs 0.9 h. The tour is close
to optimal *for its orientation* — the flow solving that part is exact — and the LP
is far below any integral solution because it is free to cover half of one direction
of a narrow pair and half of the other.

Two consequences worth carrying into Stage 5:

- **Do not read the gap as slack to be recovered by better routing.** Most of it
  cannot be reached by any feasible tour.
- **The orientation heuristic is the lever that matters**, not the deadhead routing.
  It removed only 6.1%
  of junction imbalance; SPEC §4 Stage D's orientation-flip local search is aimed at
  exactly this and has not been run here.

## 7. What this tour is not

**It is not a day plan and must not be presented as one.** It is one closed circuit
of the entire city with no depot legs, no day boundaries and no breaks. `reports/`
carries it as GPX so that it can be opened in a mapping tool and looked at — a
sanity check on the solver, not a schedule. Zoning is Stage 4 and day assembly is
Stage 5.

## 8. A correction to SPEC §4, now adopted

SPEC v0.3 §4 labelled the fixed-orientation Chinese Postman result "Stage A —
Lower bound", and I5 asserted total driving was at or above it. **That is the wrong
direction.** Fixing an orientation for every narrow pair decides something the real
problem is free to choose, which adds a constraint, which can only push the answer
up. The result is a feasible solution and feasible solutions bound from above.

SPEC v0.4 corrects both: §4 Stage A now brackets the optimum with a constructive
upper bound and an LP lower bound, and I5 asserts total driving lies **within the
bracket**. Stage 3 implements the corrected form, and the two numbers in the
headline are the bracket I5 refers to.

It matters beyond bookkeeping, and the failure it would have caused is not the
obvious one. Under the original I5 the constructive result — 88.0 h — would
have been treated as a floor. A **better** plan, anything between the true optimum
and that figure, would have *failed* a test whose job was to catch plans that were
too expensive: the invariant would have rejected exactly the improvements Stages 4
and 5 exist to find. And every optimality gap in the project would have been
measured against 88.0 h instead of 54.4 h.
